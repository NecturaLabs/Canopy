History

Each line of history has its own colour in the graph, and branches, remotes and tags are labelled on their commits. Select a commit to see its files and diff. Author pictures come from GitHub or GitLab, initials otherwise.

Blame a file, list the commits that changed it back through renames, or find the commits that added or removed a piece of text.

  • CtrlF or /Search by message, author or SHA
  • ShiftFSearch the history for changed text
  • JKNext and previous commit
  • YCopy the commit's SHA
  • ShiftTTag the commit
  • OOpen it on GitHub or GitLab

Staging and committing

Stage a file, a hunk or single lines, in a unified or side-by-side diff with syntax colours. The commit box has a subject and a body, and the Commit button says why it can't run yet.

Amending a commit you already pushed asks first. When git refuses, you see git's own message.

  • 2Open Changes
  • JKMove through files
  • SpaceStage or unstage
  • CWrite the message
  • CtrlEnterCommit

Merges and conflicts

The resolver shows both versions side by side, named by their branches: accept either, both, or edit by hand. Continue and Abort stay in view until the merge, rebase or cherry-pick is done.

Discarding, a hard reset, deleting a branch and force pushing ask first. A force push always uses --force-with-lease.

  • ][Next and previous conflict
  • HLAccept current or incoming
  • BAccept both
  • ZUndo the choice

Pull and merge requests

Review, check out and merge GitHub pull requests and GitLab merge requests, self-hosted GitLab included. Signed in with the GitHub or GitLab CLI, each row shows its checks and reviews.

Filter by checks, review, draft or author. When a project has more than 100, the search goes to GitLab, or to GitHub when signed in with the GitHub CLI.

Canopy stores no token: it uses the gh or glab sign-in and keeps it in memory only.

  • 3Open pull requests
  • CtrlShiftAApprove
  • CtrlShiftMMerge, after you confirm

The requests shown are Canopy's built-in demo data. The CLI's sign-in is only ever sent to the host it belongs to.

Your git settings

Canopy runs your own git, so credential helpers, SSH keys, hooks, signing and LFS work as they do in a terminal.

Where your git configuration makes a choice, it decides. Everywhere else Canopy passes its own choice to git, and Settings → Git shows each one beside its recommendation and where your configuration sets it.

  • A pull is fast-forward only, and asks Rebase or Merge when branches diverged.
  • A pull that would conflict names the files first.
  • After a fetch that prunes, local branches whose remote branch was deleted are removed with git branch -d, so only merged ones go. Settings → Git → Remove deleted branches turns it off.
  • Canopy writes no git configuration until you turn on Settings → Git → Edit my git config. It is off by default.
  • With it on, Use recommended writes the recommendations to your global git configuration after you confirm, and leaves signing, hooks, identity and line endings alone.

Keyboard

CtrlK opens the command palette, with every command and every branch to check out. ? shows every shortcut. Lists take vim motions and single-key actions, as in lazygit.

  • Super is never bound: it stays your window manager's.
  • Bare keys never fire while you are typing.
  • P pulls, ShiftP pushes, F fetches.
  • Settings → Keyboard changes any key, and refuses one another command already uses.

Themes

Midnight is the default and Daylight the light theme. Observatory has navy backgrounds and a periwinkle accent. High contrast works with any of them, from Settings, the toolbar's theme menu or the command palette.

A theme of your own

In Settings → Appearance, start from Midnight or Daylight, then pick an accent and a tint for backgrounds, lines and text. Text keeps at least the base theme's contrast, and the graph, syntax and diff colours keep their hues.

Shown: accent hue 150, with a tint of 40 at the same hue.

What Canopy sends

Canopy's own requests wait until you accept the terms and answer the crash-report question, and each has an off switch.

Privacy PolicyTerms of ServiceSource code

It contacts

  • Your remotes, through your own git with your SSH and credential setup.
  • Your repository's GitHub or GitLab, for pull requests and author pictures, and the picture hosts they name.
  • GitHub, to check for a new build: by itself at most once a day, which you can turn off, and whenever you choose Check for updates. A new build is downloaded only when you choose Update.
  • NecturaLabs, through Sentry, for crash reports, only if you say yes. Your computer's name and home folder are removed first.

It has no

  • Telemetry or analytics.
  • A Canopy account, or a sign-in of its own.
  • Server of its own between you and your code.

Download

Always the latest build.

Canopy is a desktop app for Linux, macOS and Windows. Open this page on a computer to install it.

Install with one command

$ curl -fsSL https://canopy.necturalabs.com/install | sh
  • The address redirects to the installer script in the public NecturaLabs/app-updates repository on GitHub, so you can read it before you run it.
  • Installs for your user only, without sudo or administrator rights: into ~/.local/opt/canopy on Linux and %LOCALAPPDATA%\Programs\Canopy on Windows.
  • Checks the archive's SHA-256 against the published checksum and stops if they differ.
  • Run it again to upgrade. It leaves an uninstaller in the install folder, and uninstalling keeps your settings.
  • Canopy needs git 2.30 or newer on your PATH. The installer never installs it for you.
